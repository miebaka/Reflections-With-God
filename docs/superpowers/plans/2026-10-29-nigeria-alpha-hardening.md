# Phase 8 — Nigeria Alpha and Public-Readiness Hardening

**Status:** Engineering foundation implemented on 2026-10-29; external evidence gates remain open.

## Goal

Turn readiness into a fail-closed evidence system. Engineering checks may be automated; content, theology, safety, privacy, legal, accessibility, real-device, and participant evidence must remain blocked until accountable reviewers provide verifiable artifacts.

## Task 1 — Release evidence and target gates

- Define immutable evidence records with artifact digests, owners, review dates, expiry, and target applicability.
- Evaluate developer build, internal alpha, Nigeria closed beta, and public release independently.
- Never infer approval from a passing build, present document, or self-asserted boolean.

## Task 2 — Staged rollout and rollback

- Enforce ordered stages and evidence re-evaluation before every increase.
- Halt or roll back on privacy incidents, critical theological/content reports, stale safety resources, excessive crashes, or unresolved safety incidents.
- Keep participant recruitment outside the application and require legal-adult consent evidence.

## Task 3 — Migration and performance harnesses

- Add an ordered, fail-closed migration registry with no partial writes.
- Set explicitly provisional engineering budgets for cold meaningful content, local interactions, journey planning, and encrypted-record operations.
- Record measurements by device profile; do not claim mid-range Android performance without real-device samples.

## Task 4 — Accessibility and CI

- Strengthen roles, states, groups, headings, live regions, and minimum touch targets in critical screens.
- Add automated contract tests and document the manual screen-reader, font-scaling, contrast, reduced-motion, and Android-device matrix.
- Run TypeScript, all tests, Expo diagnostics, GitHub Quality, and a fresh APK build.

## Non-goals

- No external approval, participant result, safety-resource verification, legal decision, penetration result, or manual accessibility pass may be generated by code.
- A new debug APK is a developer artifact, not authorization for participant distribution.

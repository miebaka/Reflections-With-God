# Reflections with God MVP Delivery Phases

**Spec:** `Reflections With God PRD.md`

The PRD covers several independently risky systems. They will ship through separate implementation plans so each phase leaves working, testable software and never treats unverified safety, privacy, licensing, or theology as complete.

## Phase 0 — External release prerequisites

Owners complete these in parallel with engineering. They block participant release, not local development with clearly marked fixtures.

- Written authorization for the single Bible translation and its attribution, storage, and redistribution model.
- Versioned editorial constitution and contentious-doctrine exclusion register.
- Named pastor, biblical scholar, content editor, and qualified safety reviewer.
- Reviewed Nigeria crisis, pastoral, clinical, and emergency resources with owners and review dates.
- Privacy architecture, threat model, retention/deletion design, and consent language.

## Phase 1 — Offline journey engine

Build deterministic, framework-independent rules for confirmed mood selections, emotional direction, invisible arc stages, approved-content filtering, same-day duplicate prevention, grounding fallback, unit state transitions, optional check-ins, late starts, and catch-up. Integrate the contracts into the current morning check-in and journey preview without claiming production content readiness.

Detailed plan: `docs/superpowers/plans/2026-10-26-offline-journey-engine.md`

## Phase 2 — Local-first application experience

Create the full accessible screen flow: eligibility and consent, morning check-in, direction confirmation, timeline, complete Scripture unit, quiet fit feedback, optional check-ins, catch-up, final mood check, neutral recap, Sunday posture, settings, and private history. Add an application reducer and repository interfaces, then persist locally on a trusted device with retention enforcement. No cloud sync yet.

## Phase 3 — Editorial content package and operations

Define the signed/versioned content-package schema, license record, dual approvals, retirement/rollback, prayer blocks, prohibited-language checks, and coverage simulator. Build ingestion and validation tooling before loading any production Scripture text. A package cannot activate unless all enabled states pass the PRD coverage matrix and adversarial replay.

## Phase 4 — Notifications, offline scheduling, and timezone recovery

Implement Gentle, Rhythm, Companion, and Silent modes; defer permission until after meaningful value; schedule discreet pushes; silently unlock timeline units; cache the active day; queue offline actions; and reconcile late starts, travel, daylight changes, and app restarts without duplicates or notification bursts.

## Phase 5 — On-device safety boundary

Introduce the on-device risk-screening interface for every text-capable surface, strong-sadness nudge, explicit-risk interruption, verified Nigeria resource package, safety confirmation, and reviewed comfort resumption. Safety policy thresholds and resources remain data-controlled and signed off by qualified reviewers; raw private text never reaches telemetry or a server.

## Phase 6 — User-controlled encryption and ciphertext sync

Threat-model and implement device-generated keys, encrypted local records, trusted-device transfer, recovery-secret confirmation, key rotation, ciphertext-only cloud sync, irrecoverable-loss explanations, retention queues, deletion, and account recovery that cannot decrypt private history. Add independent cryptographic and deletion review gates.

## Phase 7 — Privacy-safe learning and optional deeper analysis

Add explicit feedback precedence, decaying behavioral signals, correction reset, allow-listed analytics, and the specific per-reflection opt-in path. External analysis remains disabled unless zero-training and zero-persistent-retention guarantees are contractually and technically verified.

## Phase 8 — Nigeria alpha and public-readiness hardening

Run accessibility, mid-range Android, intermittent-network, battery, performance, migration, rollback, penetration, content, safety, privacy, and anti-gamification testing. Operate the provisional metrics without logging private content. Alpha and beta use staged rollouts; public release requires every PRD gate and accountable approval.

## Dependency order

Phases 1–2 establish the product behavior. Phase 3 supplies approved content. Phase 4 consumes the journey and content contracts. Phase 5 must exist before Phase 2 gains free writing. Phase 6 precedes all cloud private history. Phase 7 depends on Phases 5–6. Phase 8 validates the assembled system and cannot waive any earlier gate.
